# eBPF fleet 0.2.0

**Record Linux kernel activity once, query it locally, replay it anywhere,
and roll policy across the fleet.**

## The local-first release

`ebpf-fleet` is the new front door. It records process and file activity into
a self-contained `.fleet` bundle with Parquet events and a checksummed
manifest, queries it with SQL, replays it as JSON, compares two recordings,
and opens a live/bundle TUI — without PostgreSQL, Kafka, ClickHouse, OIDC,
Kubernetes, or the dashboard.

```bash
sudo ebpf-fleet record --for 30s --out /tmp/incident.fleet
ebpf-fleet query /tmp/incident.fleet \
  "select path, count(*) as n from events where kind = 'FileOpen' group by path order by n desc limit 10"
ebpf-fleet replay /tmp/incident.fleet
```

## Highlights

- Static-pie x86_64 release binary; no runtime toolchain or glibc dependency.
- Four/five-kernel compatibility evidence: Ubuntu 24.04 (6.8), Ubuntu 22.04
  (5.15), Debian 12 (6.1), Debian 13 (6.12), and Fedora 42 (6.14) all pass.
- Process exit events fixed by moving to the regular sched_process_exit
  tracepoint.
- File sensor decodes syscall arguments through `pt_regs`, covers `openat`,
  and avoids duplicate opens when the BPF LSM path is active.
- `fleet top` live/bundle TUI and `policy test` bundle replay.
- C probe SDK: `fleet probe build/verify/explain`; privileged verifier
  acceptance proven in the local KVM guest.
- Scoped rootless Podman wrapper and a disposable local KVM lab.
- License, DCO, security, positioning, runbooks, and checked-in evidence.

## Verification

- `cargo test --workspace`, `cargo fmt --check`, and workspace clippy pass.
- Five-kernel matrix PASS 5/5 with the exact release binary; evidence in
  `docs/verification/kernel-matrix.md`.
- Clean Ubuntu 24.04 guest extracted the release tarball and ran version,
  doctor, probe verify, record/query/replay.
- The installer verifies SHA-256 and cosign, then runs the installed binary.
- The signed artifact's public key, signature bundle, checksums, and SBOM
  are published as release assets.

## Known limitations

- arm64 is not verified on this x86_64 lab host.
- Stack capture/symbolization is not in 0.2.
- The C probe SDK verifies loadability; it does not attach probes or decode
  SDK events in the runtime yet.
- The keyless GitHub Actions release workflow is blocked by Actions billing;
  this release uses an explicit local cosign key. The public key is published
  with the release, and the same installer supports keyless releases later.
