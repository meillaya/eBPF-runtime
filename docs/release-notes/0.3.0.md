# eBPF fleet 0.3.0

**Record kernel activity, see the code path, run your own probes, and
answer the question locally.**

## Highlights

- **Stack traces:** process/file events can carry symbolized kernel and
  user stacks; bundles expose a `stacks` table and `top` shows a stack pane.
  `--stacks events` is the default; `off` keeps the 0.2 overhead and `all`
  adds fork/exit/unlink/rename stacks. Raw addresses survive symbolization
  failures.
- **Custom probes run now:** a pinned YAML manifest, dynamic load/attach,
  FPRB decode, `probe run` to JSON lines or a bundle's `probe_events` table,
  clean unload, and root-only explicit opt-in.
- **arm64:** static aarch64 artifact, installer arch selection, native
  arm64 release runner, and a real aarch64 TCG functional row
  (`record`/`query`/`replay`, explicitly not a performance claim).
- **Daily query UX:** JSON/CSV/Parquet streaming, `--schema`, `--explain`,
  `inspect`, `diff --by process/path/stack`, record JSON/quiet/progress,
  TUI filters/pause/sort/snapshot, shell completions and man pages.
- **Measured overhead:** a reproducible benchmark harness plus KVM
  baselines for stacks off/events/all.

## Verification

- Full workspace tests, fmt, and clippy.
- Stack evidence on Ubuntu 24.04 kernel 6.8: 33k events, 0 decode errors,
  16.6k kernel + 16.6k user captures, symbolized frames with file/line;
  v1 bundle compatibility.
- Custom probe evidence on Ubuntu 24.04 kernel 6.8: 118 decoded events,
  0 errors, unloaded cleanly; negative tests.
- Five-kernel x86_64 matrix remains green.
- arm64 static cross-build + functional TCG row.
- Keyless x86_64/aarch64 release with SBOM and provenance.

## Known limits

- No native arm64 KVM row on this host; the arm64 row is TCG-functional only.
- User frames of very short-lived processes can remain raw addresses.
- File opens through the BPF LSM hook do not capture stack IDs.
- Stack-map overflow is handled fail-closed and unit-tested but not forced
  in a short lab run.
- No USDT/uprobe helpers or debuginfod yet.
