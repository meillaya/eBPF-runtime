# OCI Image Builds — deploy/oci/

Multi-arch OCI image definitions for the kernel-v1 platform. Builds the
**agent** and **control-plane** images for `linux/amd64` and `linux/arm64`
using Docker Buildx Bake with SBOM and provenance attestations.

## Prerequisites

- Docker Engine 24+ with Buildx v0.10+
- `docker-container` driver builder:
  ```bash
  docker buildx create --name k1-builder --driver docker-container --use
  ```
- QEMU binfmt registered for arm64 emulation (or a native arm64 builder):
  ```bash
  docker run --rm --privileged tonistiigi/binfmt --install arm64
  ```
- [Syft](https://github.com/anchore/syft) installed on the build host
  (for SBOM attestation generation)

## Quick Start

```bash
# Build all images and push to the default registry (ghcr.io/kernel-v1):
docker buildx bake -f deploy/oci/docker-bake.hcl --push

# Build a single target to a local OCI layout (no push):
docker buildx bake -f deploy/oci/docker-bake.hcl agent \
  --set agent.output=type=oci,dest=/tmp/agent.oci

# Override registry and tag:
REGISTRY=ghcr.io/myorg TAG=v1.2.3 \
  docker buildx bake -f deploy/oci/docker-bake.hcl --push
```

> **NEVER use `--load` for multi-arch builds.** `--load` only loads a
> single platform into the local daemon and silently masks arm64 build
> failures. Use `--push` or `--output type=oci,dest=...` instead.

## Images

| Image | Dockerfile | Runtime Base | Contents |
|-------|-----------|--------------|----------|
| `agent` | `Dockerfile.agent` | `gcr.io/distroless/cc-debian12` | Agent binary + CO-RE BPF objects |
| `control-plane` | `Dockerfile.control-plane` | `gcr.io/distroless/cc-debian12` | Control-plane binary + SQL migrations |

### Agent image

Three-stage build:

1. **bpf-compile** — compiles `bpf/sensors/*.bpf.c` into architecture-specific
   CO-RE BPF objects (`*.amd64.bpf.o` / `*.arm64.bpf.o`) using clang.
2. **rust-build** — compiles the `agent` crate binary with `cargo build --release`.
   Cross-links for arm64 via `aarch64-linux-gnu-gcc`.
3. **runtime** — distroless/cc-debian12. Contains only the binary at
   `/usr/local/bin/kernel-v1-agent` and BPF objects at `/opt/kernel-v1/bpf/`.
   No compiler, no source code, no test fixtures, no shell.

### Control-plane image

Two-stage build:

1. **rust-build** — compiles the `control-plane` crate binary.
2. **runtime** — distroless/cc-debian12. Contains the binary at
   `/usr/local/bin/kernel-v1-control-plane`, ClickHouse DDL at
   `/opt/kernel-v1/migrations/clickhouse/`, and PostgreSQL migrations at
   `/opt/kernel-v1/migrations/postgres/`. No compiler, no source code.

## Digest Pinning

All base images are pinned by digest in two places:

1. **`base-images.json`** — canonical digest manifest (resolved
   2026-07-22). Update with:
   ```bash
   docker buildx imagetools inspect <image>:<tag>
   ```

2. **Dockerfile `ARG` defaults** — each Dockerfile declares pinned
   digests as build args. Override at build time for CI promotion:
   ```bash
   docker buildx bake -f deploy/oci/docker-bake.hcl \
     --set agent.args.RUNTIME_AMD64=gcr.io/distroless/cc-debian12@sha256:<new-digest>
   ```

Mutable tags (`latest`, `stable`, etc.) are **never** used in production
references. The production Compose file (`deploy/compose/production.yml`)
references all third-party images by digest.

## SBOM Generation

Every image includes an SPDX SBOM attestation generated by
[Syft](https://github.com/anchore/syft) via BuildKit attestation:

```hcl
attest = ["type=sbom,generator=syft"]
```

Inspect the SBOM after pushing:

```bash
# Using the Docker CLI (Buildx 0.10+):
docker buildx imagetools inspect ghcr.io/kernel-v1/agent:TAG \
  --format '{{ json .SBOM }}'

# Using Syft directly on a pulled image:
syft ghcr.io/kernel-v1/agent:TAG -o spdx-json
```

## Provenance Attestation

Every image includes SLSA provenance attestation (`mode=max`), recording:

- Builder ID and build platform
- Build arguments and source metadata
- Layer-by-layer build steps

```hcl
attest = ["type=provenance,mode=max"]
```

Verify provenance:

```bash
docker buildx imagetools inspect ghcr.io/kernel-v1/agent:TAG \
  --format '{{ json .Provenance }}'
```

## Verification

### Confirm no compiler in runtime images

```bash
# distroless has no shell, so use docker create + docker export:
CID=$(docker create ghcr.io/kernel-v1/agent:TAG)
docker export "$CID" | tar -t | grep -E '(clang|rustc|cargo|gcc)' && echo "FAIL: compiler found" || echo "PASS: no compiler"
docker rm "$CID"
```

### Confirm no source code in runtime images

```bash
CID=$(docker create ghcr.io/kernel-v1/agent:TAG)
docker export "$CID" | tar -t | grep -E '\.(rs|c|h)$' && echo "FAIL: source found" || echo "PASS: no source"
docker rm "$CID"
```

### Confirm multi-arch manifest

```bash
docker buildx imagetools inspect ghcr.io/kernel-v1/agent:TAG
# Should show both linux/amd64 and linux/arm64/v8 platforms.
```

### Confirm BPF objects in agent image

```bash
CID=$(docker create ghcr.io/kernel-v1/agent:TAG)
docker export "$CID" | tar -t | grep '\.bpf\.o$'
docker rm "$CID"
# Expected: opt/kernel-v1/bpf/<sensor>.<arch>.bpf.o
```

## Production Compose

The production Compose file lives at `deploy/compose/production.yml`.
It brings up the full stack: agent, control-plane, PostgreSQL, Kafka,
and ClickHouse.

```bash
# Set required environment variables:
export POSTGRES_PASSWORD="<strong-password>"
export KAFKA_CLUSTER_ID="$(docker run --rm confluentinc/cp-kafka:7.7.0 kafka-storage random-uuid)"
export AGENT_IMAGE="ghcr.io/kernel-v1/agent@sha256:<digest>"
export CONTROL_PLANE_IMAGE="ghcr.io/kernel-v1/control-plane@sha256:<digest>"

docker compose -f deploy/compose/production.yml up -d
```

Security properties:

- **No `privileged: true`** — the agent uses granular capabilities
  (`BPF`, `PERFMON`, `SYS_ADMIN`, `NET_ADMIN`).
- **`no-new-privileges`** on every container.
- **Read-only root filesystem** on agent and control-plane (tmpfs for
  scratch space).
- **Resource limits** (CPU + memory) on every service.
- **Health checks** on every service.
- **Digest-pinned images** for all third-party services.
